# Выгрузка HiTek → 1С: работающий API

Реализовано и работает в C1CServ (маршруты `/exp2/v1/*`). Только чтение: сервис
вызывает селект-процедуры `EXP2_*_S` через fb-port и ничего не пишет в базу.

Обоснование состава выгрузки — `EXP2_1C_BUH.md` (разделы 9–10), там же почему
источник истины — движения `NOM_TRANS`, а не строки документов.

## Эндпоинты

| Метод | Что отдаёт | Курсор |
|---|---|---|
| `GET /exp2/v1/state` | доступность всех источников (диагностика) | — |
| `GET /exp2/v1/nomenclature?cursor=&limit=` | номенклатура с кодом 1С, единицей, группой, корнем каталога и сигналами типа (`ЕстьСпецификация`, `ВходитВСпецификации`) | `ИдHiTek` (NOM_ID) |
| `GET /exp2/v1/storages` | складские единицы с мерой «живости» (число движений, позиций, дата последнего) | — |
| `GET /exp2/v1/specifications?cursor=&limit=` | основные спецификации: продукция + состав | `ИдHiTek` (BOM_LIST_ID) |
| `GET /exp2/v1/requirements?cursor=&limit=` | расход материалов в производство → **Требование-накладная** | `ИдДвижения` (TRANS_ID) |
| `GET /exp2/v1/transfers?cursor=&limit=` | перемещения между складами → **Перемещение товаров** | `ИдДвижения` (TRANS_ID) |

`limit` по умолчанию 500, максимум 5000.

## Инкремент

Клиент передаёт `?cursor=<последний обработанный ID>` и получает в ответе новый
`Курсор` и флаг `ЕстьЕще`. Курсор `0` или его отсутствие = «с начала»
(fb-port превращает 0 в NULL, а NULL в процедурах означает «без фильтра»).

**При вводе в эксплуатацию курсор документов ставится в текущий максимум
`TRANS_ID`** — тогда историческая заливка остатков из 1С (99,8 % движений)
не уедет обратно в 1С. Это главная защита от «кольца».

```json
{ "response": { "ПакетВыгрузки": {
  "Сущность": "ТребованиеНакладная",
  "Курсор": 5613, "ЕстьЕще": false, "Количество": 1,
  "Элементы": [ {
    "ИдHiTek": 501, "НомерДокумента": "501",
    "ДатаДокумента": "2023-12-16T19:00:00.000Z",
    "Комментарий": "SLO01-NO/NC-P-P18 верно 04.10.18…",
    "Проведен": 0,
    "Склад": { "ИдHiTek": 401, "Наименование": "Основное подразделение" },
    "Продукция": { "ИдHiTek": 4293, "КодНоменклатуры": "00-00005002",
                   "Наименование": "SLO01-NO/NC-P-P18", "РазмерЗапуска": 8,
                   "ТребуетРучногоРазбора": false },
    "Строки": [ { "ИдДвижения": 5608,
                  "Номенклатура": { "ИдHiTek": 4298, "КодНоменклатуры": "00-00000606",
                                    "Наименование": "Винт М3х8 DIN 7985",
                                    "ЕдиницаИзмерения": "шт",
                                    "ТребуетРучногоРазбора": false },
                  "Количество": 4, "ДатаДвижения": "2023-12-16T19:00:00.000Z",
                  "ИдПартии": 3862 } ] } ] } } }
```

Блок **`Продукция`** — изделие, под которое идёт отпуск; в 1С это субконто
«Продукция» на счёте 20.01, которое бухгалтеру взять больше неоткуда.

`ТребуетРучногоРазбора: true` означает, что код 1С не найден либо у позиции
несколько разных кодов (16 позиций в базе) — такие строки грузить молча нельзя.

## Что сейчас реально выгружается

Проверено на тестовом клоне:

| Эндпоинт | Объём |
|---|---|
| `nomenclature` | 4 731 позиция (постранично) |
| `storages` | 53 единицы |
| `specifications` | 2 719 основных спецификаций |
| `requirements` | **1 документ** (док. 501, 6 строк) |
| `transfers` | **1 документ** (док. 519) |

По документам объём мал не из-за выгрузки, а из-за состояния базы: производственный
контур HiTek почти не эксплуатируется (последнее движение — 20.03.2024). Подробности
и честный разбор — `EXP2_1C_BUH.md` §10.1.

## Проверка

```bash
curl -s http://<host>:3738/exp2/v1/state
curl -s "http://<host>:3738/exp2/v1/requirements" | python3 -m json.tool
curl -s "http://<host>:3738/exp2/v1/specifications?limit=200"
```

## Чего пока нет (осознанно)

- **Квитирования (ack)** — курсор хранит клиент. Серверные пакеты `EXP2_BATCH`
  описаны в `EXP2_DESIGN.md` и добавляются, когда 1С будет реально загружать.
- **Авторизации** — маршруты открыты. Перед выставлением наружу закрыть
  токеном/IP-allowlist (сервис слушает `0.0.0.0:3738`).
- **Классификатора складов и правил счетов** — сервис отдаёт данные HiTek как есть;
  соответствие «склад/подразделение 1С» и вывод счёта (10/21/43) живут на стороне
  приёмника или в будущем конфиге (`EXP2_1C_BUH.md` §9.1–9.2).
- **Выпуска продукции** — в HiTek он не документируется (§11), выгружать нечего.
